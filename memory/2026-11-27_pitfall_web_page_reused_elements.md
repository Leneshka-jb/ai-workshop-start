[2026-11-27] [Pitfall] The web page reuses the same elements (e.g. `<details id="warnings">`) for every result, so any state the user can change on them (like `open`) must be reset once per new result, in the form's submit handler. Not in `show()`/`showWarnings`: `show()` also re-runs on every filter keystroke and project change, so a reset there undoes the user's choice while they filter (found in the review of PR #21). The vm DOM harness in tests/organization.test.ts only models properties it declares on `Node`; add new ones (`open`) there to test them, and fire `elements.filter.listeners.input` to simulate typing.
